# Waking Machine — product proposal, awaiting host approval

Status: **proposal only**. Project specifications define five concept placeholders, not an approved game. No story, gameplay, official reward, event or subscriber benefit has been authored or implemented in this pass.

Suggested direction: a short, untimed mystery read between podcast episodes, explicitly labeled original fiction rather than a real case or podcast canon. The machine illustration is a visual frame, not a test of keeping the screen awake, camera tracking, reflexes or sleep deprivation.

- **Listener interaction:** read a host-approved introduction, inspect three short clues in any order, choose an interpretation, then reveal the approved explanation. Allow retry and explicit restart. No score, countdown, random outcome, reward or entitlement. This sequence and fiction format require approval before implementation.
- **Content/assets needed:** host-approved purpose and audience; original Greek introduction, three clues, answer choices, explanation and any content warning; approved English translation; rights-cleared supporting artwork if desired. The existing original SVG can be reused. Audio is optional and would require approved recordings/transcripts and a separate playback coexistence decision; the recommended first version is text-only.
- **Frontend:** a small standalone Angular view with a deterministic Signals state machine: introduction → clues → interpretation → explanation. Bundle validated static content; no backend, account, analytics or dependencies. Proposed first version has in-session state only, with an explicit notice that reload restarts it. Persistent game progress needs a later approved storage contract; the listener IndexedDB schema stays untouched.
- **Mobile/desktop:** one reading column on mobile; clue navigation alongside the reading area on desktop. Large labeled controls, no drag-only interactions, hover requirements or orientation lock. Never pause, replace or layer sound over the podcast player.
- **Accessibility:** semantic headings and native buttons, keyboard access, focus moved to each new step heading, concise status announcements, scalable text, three-theme contrast checks and reduced motion. No flashing, timed decisions or color-only clues. Screen-reader and touch verification before acceptance.
- **Estimated scope:** roughly 2–3 frontend implementation/verification days after complete approved bilingual content is supplied, plus host content review time. One story only; branching stories, audio, saved progress and rewards are excluded from that estimate.

Host decisions required: approve or replace the listener purpose and fiction format; approve the proposed interaction and session-only behavior; supply/approve the complete bilingual content and any content warning. There is no announced release date. Structural Extras improvements can be accepted independently, but Milestone 6's complete Waking Machine experience remains blocked on this specification/content gate.
